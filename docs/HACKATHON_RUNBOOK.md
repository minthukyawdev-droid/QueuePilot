# Four-Hour Hackathon Runbook

This runbook applies to future product development after the foundation commit.

## Timeline

```text
00:00-00:15
Confirm final requirements

00:15-00:30
Review API contract and assign tasks

00:30-01:45
Parallel development

01:45-02:00
First integration

02:00
Working end-to-end MVP required

02:00-02:45
Improve core experience

02:45-03:15
Integration / deployment / bug fixing

03:15
FEATURE FREEZE

03:15-03:40
Demo polish

03:40-04:00
Demo rehearsal
```

## Critical rule

> If the core user flow is not working at Hour 2, stop optional work and focus the entire team on the end-to-end MVP.

## Operating rules

- Keep `main` runnable.
- Integrate early; do not wait until feature freeze.
- Use controlled demo data for reliability.
- Announce blockers immediately.
- After feature freeze, accept only fixes essential to the demo.
- Preserve a known-good demo path and deployment.
- Integration Lead makes final scope calls when time is constrained.
